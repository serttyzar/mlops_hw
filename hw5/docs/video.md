# Что показать на видео сдачи ДЗ 5

1. Откройте общий репозиторий `mlops_hw`, покажите папки `hw1`–`hw5` и текущий коммит (`git log -1 --oneline`). Поясните цепочку: ДЗ 3 готовит train/val, ДЗ 4 делает токены и маску лосса, ДЗ 5 обучает LoRA и сравнивает генерацию.
2. В `hw5/params.yaml` покажите базовую модель Qwen3-0.6B, пути к двум файлам из ДЗ 4, `r=8`, `alpha=16`, `lr=2e-4`, seed 42 и варианты `all_layers` / `freeze14`. В `src/train.py` покажите `evaluate()` до обучения и через каждые 10 шагов, `layers_to_transform`, сохранение токенизатора.
3. Откройте `docs/curves.png`: укажите `val loss` на шаге 0 и в конце, две линии вариантов. Назовите число обучаемых параметров, время и пик памяти каждого варианта из `docs/defects.md`.
4. Откройте `docs/compare.md`, покажите пару ответов «база / адаптер» на собственных отзывах о товарах. Это демонстрация подключения адаптера и его формата; пять примеров не измеряют обобщающее качество модели.
5. Откройте `docs/defects.md` и коротко пройдите пять причин: отсутствие валидации, завышенный learning rate, фиктивная заморозка, токенизатор вне папки адаптера, незафиксированная случайность. Для каждой назовите одно число из прогона.
6. Из `hw5` запустите `make check` **после** `make train && make compare`. В одном кадре покажите девять зелёных пунктов, строку `Все проверки пройдены` и отпечаток `tests/check.sh: 06a02208c1f0`.

Команды для подготовки терминала:

```bash
cd mlops_hw/hw5
uv sync
make train
make compare
make check
```

Если артефакты полного обучения остались на этом компьютере и код/конфиг не менялись, для записи видео достаточно повторить `make check`. Веса, данные и JSON-метрики в Git не отправляются; для демонстрации они должны оставаться локально.
